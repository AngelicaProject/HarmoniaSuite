# Firetest — headless-стенд фронта

Поднимает настоящий фронт (`src/main/resources/static/js`) в jsdom с подменённым
бэкендом: документ проекта — синтетическая фикстура (65 фраз, 2 таблицы, собирается
в `buildFixture()` внутри `run.mjs`, от файлов репозитория не зависит), список исходников —
реальный листинг кэша источников (`data/sources/<версия>/en`). Затем кликает ключевые сценарии:
пикер → открытие проекта → открытие файла → умный поиск → переключение скопа → сводка.

## Запуск

```sh
# один раз: поставить jsdom для стенда (живёт в системном tmp, репо не пачкает)
npm i --prefix "$LOCALAPPDATA/Temp/harmonia-firetest/deps" jsdom

node tools/firetest/run.mjs
```

Коды выхода: `0` — всё зелёное, `1` — есть упавшие сценарии, `3` — нет jsdom.
Если процесс висит и его убивает `timeout` — это тоже сигнал: главный поток заблокирован
(так был пойман `ReferenceError: fl`, вешавший вкладку при открытии файла).

## Что проверяется

- пикер показывает тестовый проект, проект открывается (дерево файлов непустое);
- клик по файлу включает режим фраз, строки рисуются, редактор встаёт на файл;
- бред в поиске сужает список до нуля, реальное слово даёт совпадения;
- переключатель скопа «Этот файл / Весь проект» меняет заголовок;
- сводка открывается с прогрессом, в тексте нет литерала `undefined`;
- нет Vue runtime-ошибок (тосты «Ошибка интерфейса…» валят прогон).

## Добавить сценарий

В `run.mjs` есть хелперы `check(name, cond)`, `click(el)`, `typeInput(el, text)`, `flush()`.
Новый блок — это несколько строк: найти элемент в `document`, кликнуть, `await flush()`,
проверить DOM через `check`.
